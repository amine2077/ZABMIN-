# Session 2026-07-30 (9m14s)

## Phase 1: `collector_runner.py` — 3 critical async bugs

### Bug A: `_consume_completed_futures` never reset `rs.running`
`_run_one` set `running=True`, but on the next cycle `_consume_completed_futures` saw `running=True` and skipped the collector — it never reset it to `False` after future completion.

**Fix**: Added `rs.running = False` inside `_consume_completed_futures` after detecting the future is done.

### Bug B: Stuck futures pinned `_in_flight` forever
If a background refresh future timed out (sync thread blocked), the future reference stayed in `_in_flight` forever. Future cycles detected `running=True` + `name in _in_flight` and skipped, permanently starving the collector.

**Fix**: Added `_in_flight_started` dict tracking submission timestamps. Background cycle detects stuck futures: `(now - started) > max(spec.timeout * 3, 10s)` → logs warning → continues (does NOT delete the stale entry in finally — that would cause duplicates).

### Bug C: `finally` block deleted in-flight futures on timeout
`_run_one` had `finally: del self._in_flight[name]` which ran even on timeout — deleting the future while the sync thread was still running. Next cycle submitted a duplicate.

**Fix**: `finally` only deletes if `fut.done()`. The stuck-future cleanup handles zombie futures separately.

### Changes
- Added `_in_flight_started: dict[str, float]` field
- `_run_one`: records `_in_flight_started[name]` at all submission points
- `_consume_completed_futures`: resets `running`, deletes stale in-flight
- background cycle: stuck timeout detection with max(3×, 10s) threshold
- `shutdown`: cleans up `_in_flight_started`

### Root cause of mocking bug

Extensive debugging revealed a subtle interaction: `unittest.mock.patch` of `process_iter` + `_GoodProcess`/`_BadProcessNoSuch` real classes inside `collect()` caused `except Exception: return []` to fire. The exact same logic inlined in the test passed. Root cause is likely a `module.__dict__` lookup ordering issue with how `from ... import collect` resolves globals vs patched attributes. Tests now use `MagicMock` subclasses with `PropertyMock` for process stubs, which avoids the issue entirely.
